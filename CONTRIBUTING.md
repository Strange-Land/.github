# Contributing to StrangeLand

Thank you for helping improve StrangeLand. Most contributions come from research groups who have adapted the simulator for their own studies, and we want those improvements to reach everyone.

## Reporting a problem or asking a question

Open an issue in the repository closest to the problem (for example, `strangeland.steering` for input devices). Include your Unity version, operating system, headset and steering hardware, and the steps to reproduce the problem.

## Sharing an extension from your fork

If you have added a vehicle, robot, sensor integration, scenario or analysis tool in your own fork:

1. Open an issue describing what it does and which package it extends. We will suggest where it fits.
2. Make the change against the package it extends, keeping lab-specific settings (study scripts, participant data, paid assets) out of the shared code.
3. Open a pull request. A maintainer will review it, and may ask for a sample scene or short documentation so others can use it.

Keeping your own fork is fine and expected. Contributing extensions back means they are maintained along with everything else, and your fork can keep pulling updates.

## Licensing

All code is released under the MIT license. Please do not contribute code or assets you cannot release under MIT, including paid Unity Asset Store packages.

## Data

Never commit participant data. Recorded sessions shared with the project must be de-identified and covered by the consent and ethics approval under which they were collected.

## Citing

If you publish work that uses StrangeLand, please cite the papers listed in the organization README, so that use of the platform can be tracked and supported.
